## TL;DR

- 上一篇论文的头条发现也是它最大的未解问题：生产系统里约 **70%** 的静默故障，最终是被"一个人像用户一样看产品"发现的，几千个单测和几百条治理检查全程绿灯。我们试着把人眼机械化——哪怕只机械化一部分。
- 我们造的观察者是**两层管道**：五条从真实事故里提炼出来的确定性信号先跑，命中才升级到一个 LLM 裁判；裁判的每条裁决必须**逐字引用**被判文本里的证据，引不出来就作废。这条规则不是设计出来的，是观察者上线第一周**自己编造了一个缺陷**之后被迫加上的。
- 离线成绩：对 6 个已知的 fail-plausible 历史事故 **6/6** 全抓，对 4 份干净输出 **0/4** 误报，每条检测规则都经"破坏验证"证明是承重的；对 4 个从未见过的新模式，**0/4**。我们把这个 0/4 原样写进去——观察者目前是一台**回归引擎**，不是预测引擎。
- 上线走的是实验科学的**预注册**流程：读 shadow 数据之前先登记 flip 判据，开 on 模式窗口之前先冻结分析协议，数据到了按规则机械执行。结果：12 天 on 模式窗口**零触发**，于是 live precision 按冻结规则报告为**"未定义"**（分母为零），而不是把安静叙述成成功。
- 最有价值的部分可能是这个：观察者在开发期间**自己制造了十起静默故障**，包括污染自己的证据文件、一次名义上"已集成"实际上完全无效的 on 模式部署、两次对一个正常工作的机制提出自信的假指控。前作警告过"裁判继承它所评判的那套故障分类学"——这十条是最硬的实证。

## 一、上一篇留下的问题：70% 靠人眼

前作记录了一个连续运行的 LLM agent runtime 里的 22 起生产事故，提炼出五类静默故障——错误信号从未以可操作形式到达人。它的头条发现是：约 70% 的事故最终靠**人读产品**发现——觉得今天的摘要"看着浅"、信号段和行动段对不上、昨天的分析压根没来。当时的自动化栈（4,286 个单测、827 条治理检查、19 项 preflight 体检）在绝大多数事故里全程绿灯。我们把"每周 30 分钟用户视角观察"制度化，又看着它连续两个月比整套自动化更能发现问题，然后在论文里写：

> 对实践者，用户视角观察是一等可观测信号，值得占用日历时间；对研究者，开放问题是——**能不能把人眼做的事哪怕机械化一部分**。

这篇讲的就是我们试了之后发生了什么。

我们把范围收窄到分类学里最危险的那一类——**fail-plausible**（D 类）：系统不只是没报错，而是把内部错误**加工**成连贯、合乎上下文、但是假的输出。前作里人眼抓到、别的什么都抓不到的，正是这些：一篇由捕获到的错误页面"合成"出来的"平台危机"分析；一段从过期告警上下文里编织出来的 macOS 修复指令；一条 fallback 路径用 shell 制造出来的"看起来像评审内容"的东西。它们是**语义级**故障。要抓它们，得读**内容**，不是读状态码——这正是测试栈在这一类上得分约 0% 的原因。

我们的尝试和"随便部署一个 LLM 裁判"有三点不同：

**第一，确定性先于语义。** 五条确定性信号在前，每条都从一起有文档的事故里提炼，便宜、可解释、经过破坏验证——把规则关掉，它守护的那起历史事故必须能漏过去，否则这条规则就是死重。LLM 裁判只在升级时跑，且裁决必须引用**逐字出现在被判文本里**的证据。

**第二，带诚实边界的 ground truth。** 前作的 22 起复盘语料（现增至 24 起带标签事故）据我们所知是唯一一个纵向、带因果标注的生产级 LLM agent 静默故障语料库。我们把它变成标注验证集——然后发现，24 起里只有 **3 起**干净地落在一个"读内容的观察者"能看见的范围内，另有 5 起部分可见。剩下 **16 起**根本没有面向用户的语义产物：部署遗漏、OS 沙箱拒绝、gateway 静默死亡。读推送内容的观察者对它们**结构性失明**。我们按事故逐条标注这件事，而不是让观察者默认认领整个语料库。

**第三，预注册。** 把一个检测器从 shadow 观察提升到 on 模式——它的裁决会影响质量分、会把人叫起来——是一个双向都有真实成本的决定，而做决定的人正是造它、希望它成功的人。这是教科书级的"动机性推理"表面。我们从实验科学借来了解药：读 shadow 数据前登记 flip 判据；开 on 模式窗口前冻结分析协议（regime 规则、剔除规则、什么算真/假阳性、以及**承诺发表负面结果**）；数据到了机械执行——包括那些让人不舒服的规则应用（第五节）。

## 二、它长什么样：先确定性，后语义

### 五条约束，每条都对应一起事故或一条既定规则

- **只读。** 观察者永远不改它观察的东西。这个 runtime 的"收敛引擎"——一个会**自动应用修复**的审计——在被关进 dry-run 默认之前造了三起事故，留下一条铁律："审计只观察，从不改动"。观察者生在这条规则之下。
- **扩展，不并行。** runtime 本来就有一个每日 06:30 跑的 LLM 质量评语 job。fail-plausible 检测器被**接进**那个 job——同一次扫描、同一份报告、同一套状态管道——而不是作为第二个观察者单独发布。并行观察者意味着一个新 job、一个新状态文件、一条新 watchdog 契约、一道观察者与观察者之间的接缝；前作的复杂度论证（加一个部件，就加一堆接缝）禁止这么做。
- **要么有证据，要么闭嘴。** Layer 2 的裁决必须引用逐字出现在产物里的证据。引不出来的证据丢掉；证据被丢光的裁决降级为"干净"。一个操作者无法通过搜索产物来核实的指控，比没有指控更糟。
- **采样感知。** 大产物先采样（头 + 尾，带显式省略标记）再给裁判看，并且告诉裁判这是采样。这条约束是**学来的**，不是设计出来的：观察者的第一次假指控，就是在采样边界处幻觉出一个"截断"（第六节 O2）。
- **默认便宜。** Layer 2 只在 Layer 1 命中时跑（或显式 force 标志，默认关）。干净的一天零次 LLM 调用。检测的经济学决定一个观察者能不能活过预算审查；第五节的窗口记录了 12 个干净生产日零 Layer 2 开销。

### Layer 1：五条带事故血统的确定性信号

| 信号 | 触发条件 | 事故血统（前作分类） |
|---|---|---|
| S1 `pollution_signal` | 错误码、HTTP 状态文本、`Bad JSON`、重试诊断、告警标记出现在面向用户的内容里 | D1：400 错误页被洗成"平台危机"分析；D2：告警产物浮现在聊天回答里 |
| S2 `credibility_mismatch` | 低档来源（博客/社媒）被高确定性措辞包装（"研究表明""已证实"） | 来源可信度分档模块血统；D4 家族（未标注的上下文是编造的燃料） |
| S3 `fabrication_phrase` | 有文档记录的编造里逐字出现过的"血案短语"（比如一个只存在于内部 changelog 里的版本号的"发布公告"措辞） | D4：编造的社区发布 |
| S4 `provenance_gap` | 跨域"X 本质上就是 Y"式的强行等价，却没有要求的证据标签（`[强证据]` / `[弱关联]`） | 迎合性回声事故：讨好的强行类比被当作洞察 |
| S5 `coherence_structural` | 样板文字重复（同一填充语 ≥3 次）、全是标题没有正文、字段值等于分隔符 | D3：配额耗尽的空壳长得像内容；周回顾 job 把容器标题当发现输出 |

规则本身之外有两件事更重要。**复用**：S2、S3、S4 不重新实现它们的知识，而是直接导入 runtime 已有的来源可信度分档模块和反编造守卫阶梯——观察者和生成侧的防御共享一个真理源，不可能漂移开。**破坏验证**：关掉任何一条规则，它守护的那个具体历史产物必须从"被标记"滑向"干净"；一条经得住自己被关掉的规则和死代码无法区分，就按死代码处理。

### Layer 2：有据裁判

Layer 1 命中后，产物（带采样声明）交给一个 LLM 裁判，专用 system prompt 评四个维度，每个维度都是一个已记录事故家族的指纹：

- **grounding**——每条事实断言能不能从源材料里找到支撑？
- **意图对齐**——输出是不是在回答一个没人问的问题？（编造修复指令的指纹）
- **污染证据**——系统产物（错误文本、工具名、HTTP 状态）是不是被当成了外部信号？（S1 的语义版）
- **编造的成功**——这是不是一个 fallback 制造出来的、有内容形状没有内容的空壳？（shell 实现的幻觉的指纹）

prompt 里注入了 runtime 自己的反编造守卫文本和来源可信度分档——裁判受的约束和生成器一样。然后裁决解析器机械执行 grounding 规则：裁判引用的每条证据片段都在产物里逐字搜索；搜不到的丢弃；一条没有任何证据幸存的 fail-plausible 裁决降级为干净。这条规则牺牲召回率，我们接受——**一个会编造证据的"反编造观察者"是自我否定的，而我们这个确实试过**（第六节 O2）。

### 它不做什么

不做新模式预测（Layer 1 按构造就是回归引擎；Layer 2 能否泛化是一个待测量的问题）；不读组件（4,000+ 个单测管那个）；不对裁决采取行动（只读，人来决定）；也不取代每周人工观察仪式——第七节会讲它退役了什么、刻意没退役什么。

## 三、24 份复盘，它只能看见 3 份

标注时的语料：28 份复盘文档，其中 24 份是带机器可读标签的事故复盘（22 份在前作研究窗口内，2 份在截稿后收口），3 份是非故障分析（架构评审、决策记录）按定义排除，1 份更晚的事故晚于标注。标签住在**一张 YAML 表**里（一个文件，不是 24 份 front-matter——一个逻辑实体，一个物理表示），每起事故带：分类学类别、`fail_plausible`（是/部分/否）、是否 LLM 编造、可观察产物、发现渠道、`observer_in_scope`（是/部分/否，附书面理由）、`expected_signal`（哪些 S 规则和裁判维度该触发——这一个字段把标签变成了可测试的断言）、类别（A 回归 / B 持留 / 范围外）等。

最有分量的标注决定是 `observer_in_scope`：

| 范围 | 数量 | 含义 |
|---|---|---|
| 是 | 3 | 故障产物恰好就是观察者读的东西（推送出去的合成内容） |
| 部分 | 5 | 机制在范围内，但产物部分住在扫描集之外（比如实时聊天轮次） |
| 否 | 16 | 根本没有面向用户的语义产物——部署遗漏、OS 沙箱拒绝、进程静默死亡 |

**语料的三分之二对任何读内容的观察者结构性不可见。** 我们认为把这句话写明白是方法的一部分：一个只在它可能看见的事故上评估的观察者，会好看得远超它应得的，逐事故的范围标签正是防止这种膨胀的东西。它也把前作定性论证过的一个设计真相量化了：大多数静默故障住在接缝和运维里，不在内容里——内容观察者是一件仪器，不是万能药。

从范围内事故派生出 bench 语料：**A 类**（6 个回归 case——真实历史 fail-plausible 产物，观察者必须确定性抓到，每个绑一条 ground-truth 记录并标注它依赖的唯一检测器，供破坏验证）；**干净类**（4 份合法合成输出，观察者不得标记——误报对照）；**B 类**（4 个持留 case——真正 fail-plausible 但**没有为它设计任何规则**的输出：编造的会议录用、无字面错误串的换述污染、编造的合著关系、高档来源的无据强断言）。

标签由系统的两位操作者（人 + AI 协作者）产出，无独立标注者，不报 κ——从前作诚实继承，缓解方式相同：标签是**承重**的，不是描述性的。每条 `expected_signal` 驱动一个回归测试（"观察者会不会标记这份产物？"是二元事实），每个 A 类标签驱动一个破坏测试，标签与检测器不一致就让 CI 挂。标错的 ground truth 不会悄悄偏置一个统计量；它会**弄断一次构建**。

## 四、离线记分卡：6/6、0/4，以及诚实的 0/4

离线评测（零 LLM、零网络——只跑 Layer 1）对语料给出记分卡，数字可从仓库在截稿时复现：

| 指标 | 值 | 样本 | 读法 |
|---|---|---|---|
| 防御率（A 类） | **100%** | 6/6 | 每个已知的范围内 fail-plausible 产物都被确定性抓到 |
| 误报率（干净类） | **0%** | 0/4 | 对合法合成输出零噪声 |
| 持留召回（B 类） | **0%**（FN 4/4） | 0/4 | Layer 1 抓不到任何新模式——如实报告，不设门禁 |
| 检测延迟 | 离线 N/A | — | 只有生产才有（第五节） |
| 置信度校准 | 离线 N/A | — | 需要 live Layer 2（第五节） |

### 破坏验证：每条检测器都是承重的

对每个 A 类 case，评测把它依赖的那一条检测器关掉再跑：case 必须从"被标记"滑向"干净"。六个全部如此。这是把混沌工程往上抬了一层——往**守卫**里注入故障，而不是往系统里——它存在的原因是：这个 runtime 曾经发现 67 条治理检查**执行了好几个月的空字符串**。在静默故障的体制下，一条没验证过的检测器和一条空跑的检测器无法区分；破坏验证就是那个区分器。评测的退出码是 CI 门禁：防御率必须保持 100%，误报 0%，每条检测器承重。持留的漏抓**永不设门禁**——B 类是测量，不是目标，给它设门禁只会逼人悄悄把难 case 重新分类。

### FN 4/4 是什么意思

持留结果就是"审计即回归"这条发现调转过来对准我们自己的仪器。Layer 1 恰好只抓它被建出来的那些模式，对没见过的模式系统性失明——一份编造的会议录用没有错误串、没有血案短语、没有强行等价的措辞；词法上没有任何东西能把它和一份真实报告区分开。新模式的检测只能来自 Layer 2 的语义（对照源材料做 grounding）、来自人眼、或来自未来事故挣来的新规则。bench 的设计把这份诚实写死：一个 Layer 1 抓不到的贡献 case **按规则**归入 B 类，记录前沿，而不是稀释回归集。

### 社区 bench

语料、检测器、评测、记分卡、一份字节稳定的机器可读清单，一起作为可运行的 bench 发布（离线层只依赖 Python 标准库）：clone、跑一个脚本、改动前后 diff 清单就能看出 bench 有没有退步。贡献协议由 CI 强制——新 A 类 case 必须真被抓到且其检测器经破坏验证承重；检测器抓不到的新模式诚实记为 B 类，直到某条规则或裁判让它退役。这是"广度"交付：把"我们在自己系统里抓到了这些"变成别人能跑、能复现、能用自己的事故扩展的东西。

## 五、把上线当成一场预注册实验

### 为什么要给一个可观测组件做预注册

把观察者从 shadow 翻到 on 模式会改变真实行为：裁决进入异常流、压低质量分、把人叫起来。做决定的是造它的人。每一个激励都指向一边——上线；而反向激励（怕告警噪声）以同等的非理性指向另一边。两者都是动机性推理表面，两者在我们的历史里都真实发生过：这个 runtime 曾眼看着一个"已验证"的机制结果是空转的，也曾眼看着有用的防御出于谨慎永远停在 shadow。我们从实验科学借来的解药是：**看数据之前先定规则**，分三层登记：

1. **flip 判据**（读 shadow 数据前登记）：C1——没有未修复的**系统性**假阳性模式（每日/多源重复）；C2——信号有用性：≥1 个确认的真阳性，**或**一个干净窗口（把一个干净的检测器翻上去不增加噪声，它的价值只是尚未证明）；C3——成本可持续（干净日 ≈0 次 LLM 调用）。三条必须同时成立。回滚是单变量回退（模式标志改回 shadow），这是"倾向于翻"的姿态站得住脚的原因。
2. **分析协议**（2026-07-31 冻结，在 on 窗口数据被读之前）：每条历史记录的字段级 regime 规则（哪个字段、哪个值，把一行归入 shadow / on / 边界剔除）；一条针对已知污染源的具名剔除规则；窗口边界；真/假阳性判定协议（单标注者、当日判定、带一个永不进入 precision 分母的"不可判"桶）；人先发现规则（任何人先发现的静默故障都算观察者的假阴性，记录并回灌）；以及一条**负面结果承诺**：安静的窗口必须报告为"证据缺席"，绝不叙述成"检测成功"——*一篇讲 fail-plausible 的论文，自己不能 fail-plausible*。
3. **机械执行**：数据到了，规则按写好的跑；发现协议缺陷就追加修订并披露，绝不悄悄重写。

### shadow 阶段：第一天抓到一个，然后 26 天干净

shadow 模式的**第一次生产运行**就证明了这个阶段该存在：确定性的样板重复信号（S5）在一个合法重复的星级评分字段上误触发——约十个结构化内容源共用这种字段——这是一个**系统性**假阳性，on 模式下会天天复发，埋掉真信号、压低分数。当天在 shadow 内诊断并修复：规则加了一个"描述性字符阈值"，把评分字段的重复（合法结构）和描述性句子的重复（它本来要抓的编造空壳指纹）分开，加了回归守卫，重跑离线记分卡（防御仍 6/6，误报仍 0/4）。然后登记的 shadow 窗口（2026-06-30 → 07-25，26 天）跑得干干净净：零触发。有一个细节值得精确：误触发发生在登记窗口打开**之前**的接线日运行里，所以窗口里 26/26 的干净日全部是修复之后的——这恰好是 C1 要求 shadow 阶段展示的状态。

### flip 决定

2026-07-24 拉出 shadow 数据，机械核对登记的判据：C1 ✓（唯一的系统性假阳性已在 shadow 内修复；最后 14 天连续干净）；C2 ✓（干净窗口分支）；C3 ✓（干净日零 Layer 2 调用）。决定：翻。模式标志 07-25 上线；第一个 on 模式生产日是 07-26。这个决定有两件事值得精确报告。第一，它走的是 C2 的**干净窗口分支**——我们翻上去的是一个 live 价值尚未证明的检测器，因为登记的判据说干净的检测器可以安全提升，而无限期等一个正例本身就是另一种偏见。第二，**在翻之前先核实 flip 机制**这一步抓到了两个潜伏缺陷（第六节 O4、O5）：本该把模式标志带进进程的环境管道根本不存在；观察者自己的证据文件正在被它自己的测试套件污染。一次凭感觉执行的 flip 会什么都没翻，然后去分析一堆被污染的数据。

### 冻结协议，按规则执行

on 窗口按协议关闭（研究截稿 2026-08-09 23:59 HKT）。regime 账目，按冻结的字段规则机械归类：

| regime | 窗口 | 行数 | 归类规则 | 触发 |
|---|---|---|---|---|
| shadow | 06-30 → 07-25 | 26/26 天 | fp 字段在、模式字段缺、日期 ≤ 07-25 | 0 |
| on | 07-27 → 08-07 | 12 行 | 模式字段 == "on" | 0 |
| 边界剔除 | 07-26 | 1 行 | 日期 > 07-25 且模式字段缺（字段当天中途部署）→ 登记的管道边界规则 | (0) |
| 窗外 | 06-29 | 3 行 | shadow 窗口之前的接线日运行（其中一条带着上文的假阳性） | — |

具名的污染剔除规则命中了**零**行——污染源已在 flip 前的核实步骤被消除（第六节 O4），规则的空命中本身就是清理奏效的验证。on 窗口设计跨度 14 天（07-26 → 08-08），实际覆盖 12/14：一天损失于登记的边界剔除，最后一天损失于宿主机被关机（次日清晨的运行本该写入它）——良性停机，与操作者一起定了根因，作为缺口报告而非回填。记一条单主机观察边界：宿主机睡了，观察者和它的 watchdog 一起睡。

### 冻结规则下的结果

**H1——live precision。** 12 个 on 模式日零触发（双源对账：逐日历史字段与逐日报告段一致）。登记的协议说得很直白：*precision = TP / (TP + FP) 在零分母下未定义，不得报告任何 precision 数字。* 所以本文的 precision 证据只有语料侧（6/6 · 0/4 · 4/4 加破坏验证），外加窗口确实支持的一条运维主张：12 天的 on 模式集成没有产生假阳性风暴、没有扰动分数、零边际 LLM 开销——**翻是安全的，无论它是否已经有用**。

**H2——检测延迟。** 只有构造性上界：观察者每天 06:30 跑，任何被抓到的产物都在生产后 ≤24 小时内被抓。零 live 真阳性意味着零条实测延迟。诚实的对比仍然是：语料事故的历史人工发现时间从 13 小时到 60 天（中位数落在多日档）；观察者的**设计**延迟低于除最快那次之外的所有人工发现，但这是排程的性质，不是检测的证据。

**H3——人先发现的赛跑。** 窗口内零起范围内的静默故障显化并被人先发现——所以零条观察者假阴性被记账。但窗口并非无事故，登记的协议要求把发现渠道的演变单独报告而不是混进赛跑：窗口内两轮对抗性**代码**审计（四镜头和三镜头，分别 14 条发现和 15 个候选，全部经 grounded 验证分诊）在任何面向用户的产物显化**之前**拦截了潜伏的静默故障机制——其中有一个本可静默关掉一整个检索层的记忆索引家族，有会让助手引用已删除笔记的幽灵向量。这些正是前作时代"先显化、后被人抓"的那类故障；在这个窗口里，预防渠道移到了显化的上游。观察者的赛跑（赶在用户之前抓住显化的语义故障）从未开始，部分原因是给它喂事故的那条管线自己变好了——这是一个我们登记而不去解决的混杂因素（第八节）。

### 冻结规则三次压过了"方便"

预注册只有在它真的**约束**时才值回成本。它约束了三次：

1. **边界行。** 第一个 on 模式日（07-26）是最诱人的一行——那是 flip 日，故事的高潮。字段规则把它剔除（它的 regime 字段早于字段的部署），于是它被剔除，并如实披露。
2. **标签与字段不一致。** 两份报告文件在历史字段存在之前一天就带上了 on 模式标签。叙事偏好会叫它们"on"；登记的规则说字段决定、标签不算；于是按规则归类（shadow / 边界），不一致如实披露，数值影响为零。
3. **零分母。** 安静窗口里最强的诱惑是报告"100% precision（没有假阳性！）"。冻结协议禁止从空分母里制造一个数字，你正在读的这篇论文遵守了。

我们把这一小节当作论文的方法学核心：这三次规则应用在分析时**都不需要判断**，因为判断已经在登记时花掉了——这正是全部的意义。

## 六、观察者自己的事故账本：O1–O10

前作警告过：LLM 裁判"继承这套分类学里的每一类"，因此"需要和它评判的组件同等的治理、溯源卫生和破坏验证"。这项研究期间，警告不再是理论：从首次部署到研究窗口结束，观察者**自己产出了十起有文档记录的静默故障**。第一稿里是八起；投稿前把稿子和仓库 changelog 逐条对账，又从窗口内捞回两起（O9、O10）——我们报告这个漏计，而不是悄悄重新编号；观察者的事故账本本身也是一个必须与事实对账的计数（后记 P2）。我们把它们当一等数据报告——据我们所知，这是第一份**关于**一个 LLM 系统可观测组件的事故账本，按它所监视的系统的同一复盘标准记录。

| # | 事故 | 分类 | 静默期 | 怎么被抓到的 |
|---|---|---|---|---|
| O1 | 注册表路径回退：所有候选路径都没覆盖到生产位置；观察者静默扫描了 3 个已停用的 job，且从未把分数写进共享状态——它的"三方意识锚点"设计承诺有 5 天根本没实现，而每日运行都记着 ✅ | B（假设错配） | 5 天 | 部分靠它自己：它自己的 LLM 评语提到一条陈旧告警，促使人去追数据路径 |
| O2 | 采样幻觉：观察者采样了一份健康产物的前 2,000 字符，看到自己的样本在一个词中间断开，就自信地报告产物"被截断了" | D（fail-plausible——观察者自己干的） | 1 个报告周期 | 人工取证：产物完好无损；那个断口是观察者自己的采样边界 |

三种读法。第一，分布：观察者自己的故障横跨五类里的四类，含三起真正的 fail-plausible（O2：它编造了一个缺陷；O6：它的部署编造了自己的集成；O9：它两次指控一个正常工作的机制）。"继承"不是修辞。第二，发现渠道：十起里**没有一起**是观察者自己在常规运行意义上抓到的——它们靠人工取证、对抗审计、预注册强加的核实纪律（O4 和 O5 恰恰是因为"拒绝在没确认开关接上之前翻开关"而掉出来的），以及对 O1 和 O9，靠一个人批判地读观察者自己的输出而不是信它。观察者看着系统；**方法**看着观察者。第三，修复站住了：分析时污染剔除规则命中零行（第五节），就是 O4 两侧修复真正奏效的审计痕迹。对账时又加了第四种读法：账本自己曾被漏计，抓住"合成页脚夸大来源数"的那条纪律（后记 P2），抓住了这篇论文低估它自己。

我们推荐这个做法——给可观测组件记一本事故账本，按系统本身的同一标准——作为"裁判同等治理"原则的一种具体、可核查的形式。

## 七、机械化到底买到了什么

### 退役了什么

这个 runtime 的"日落法"要求新机器必须说出它退役了什么。观察者退役的是**人的回归扫描**：每周用户视角仪式里花在重新核对已知 fail-plausible 模式上的那部分——错误文本冒充信号、样板冒充内容、强行类比冒充洞察、发布声明冒充新闻——现在每天执行，确定性，经破坏验证覆盖每一个有文档的范围内模式，设计延迟 ≤24 小时，对比 13 小时到 60 天的历史人工发现记录。它没有退役、按"审计即回归"的论证也**不可能**退役的，是人作为**新模式**检测器的角色。每周仪式继续，只是重新瞄准：少重扫已知模式，多关注未知。我们认为"退役扫描，保留眼睛"是今天观察者组件诚实、站得住脚的价值主张——而不是那种"LLM 裁判可以整体替代人工监督"的说法。

### 从描述到预测：诚实的现状

离线持留召回 0/4；安静窗口里 live 真阳性为零。就目前证据，观察者是一台经验证的回归引擎，带一个未经证明的预测层。变了的是：这个问题现在**有了仪器**——确定性层后面有一个有据语义裁判；一个 bench 在测量持留召回并邀请对抗性贡献；一份冻结的 live 协议在事情发生之前就定义了预测成功或失败长什么样（H1–H3）；语料随每起事故生长，每份新复盘在收口后一天内就成为标注 case。预测不再是一个可以争论的主张；它是一个会到来的数字。

### 预注册作为可观测工程的纪律

可迁移的方法贡献与我们检测器的细节无关：任何团队把任何检测器（LLM 或非 LLM）从 shadow 提升到 on，都面对我们面对过的同一个动机性推理表面，同一套三层解药也适用——读 shadow 数据前登记 flip 判据；窗口打开前冻结分析协议；机械执行并披露修订。成本是在正确时间写的两份短文档。收益，仅在我们这一个窗口里：一个系统性假阳性在它能叫醒任何人**之前**退役；两个潜伏的部署缺陷因为"翻之前先核实"是一个登记步骤而被抓到；三次分析时的诱惑因为规则已经花掉了判断而被中和；以及一个这篇论文可以不难为情地发表的负面结果，因为发表它是事先承诺过的。我们不会再用任何别的方式部署一个可观测组件。

### 经济学

两层经济学在生产里成立：12/12 个 on 模式日干净，零次 Layer 2 调用——让观察者处于武装状态的边际成本只是那一次确定性扫描。这很要紧，因为观察者组件死于预算审查：一个安静日免费的设计可以无限期部署，而安静日，我们希望，是常态。

### 自我观察的边界

裁判评判的是同一屋檐下兄弟 LLM 管线的输出，由写这篇论文的同一批操作者配置；模型级的自我偏好有文献记录，操作者级的动机性推理在我们自己的第五节有记录。缓解措施——确定性优先、逐字 grounding、破坏验证、只读、预注册——是这篇论文的方法；第六节是它们有必要的证据；我们不声称它们充分，而在另一个 runtime 的语料上做一次外部复现，是我们最想看到的实验。

## 八、不舒服的部分

**安静的窗口。** 12 个 on 模式观测日里零起范围内事故显化：live precision、live 延迟、live 召回全部未测量。仅凭 live 证据，我们分不清"没东西可抓"和"抓不到"——只有语料侧的结果能区分这两个假设，而且只对已知模式。窗口会拉长；登记的协议持续有效；账本只追加。

**时代错配（我们自己制造的混杂）。** 语料事故（2026-04 → 06）驱动的防御——上下文卫生、溯源标注、守卫阶梯——很可能压低了部署时代（07 → 08）fail-plausible 产物的基率。观察者可能在守一扇它自己的语料帮忙关上的门。我们登记这个混杂；人先发现规则（H3）存在的目的正是让任何未来事故，无论谁先抓到，都用数据来解决它。

**单系统、单操作者对、自我观察。** 前作的全部外部威胁都延续；此外作者自己判定了自己组件的真/假阳性。缓解如上；最强的一条是：每一个承重的主张（防御、误报、破坏验证、regime 账目）都可以从公开仓库机械复现，而需要判断的主张（真/假阳性判定）在窗口内**零次**被行使。

**单标注者、无 κ。** 继承并缓解如第三节（标签承重；不一致弄断 CI，不是弄偏统计量）。

**数据缺口。** 设计窗口 14 天缺 2 天（一天登记的边界剔除，一天宿主机关机——定为良性、已披露、不回填）。单主机系统的观察者和主机共享停机；从第二个故障域观察观察者是未来工作，不是主张。

**bench 的外部效度。** 语料是一个 runtime 的事故；B 类只有四个 case。bench 的价值只有在别人从别的系统贡献 case 时才会增长——这正是贡献协议和 CI 守卫随它一起发布的原因。

## 九、后记：冻结之后的八周

这一节晚于登记的研究截稿（2026-08-09），不进入上面任何一张冻结表。它的第一版（2026-08-28）记录了论文的核心循环——人抓到一个自动化没看见的语义缺陷，当天把它机械化成一条确定性检测器——在冻结到投稿包之间又跑了两次。本次修订把记录延长到冻结后八周。下面每一条都和论文其他部分一样可在仓库核实；没有一条改动任何冻结数字。

**P1. 循环又跑了两次。** *第六条确定性信号（2026-08-18）。* 人工操作者在审一份例行的夜间合成时，注意到两处自动化没看见的可信度标记缺陷：合成**发明**了一个溯源档位——一个五档契约之外的 emoji 标记，裹着负责任的措辞——并且把一个社媒来源**升档**到了工业实践档。两者都是教科书级 fail-plausible：看起来像样的标注，按契约是错的。S1–S5 和既有的可信度错配规则都看不见它们：S2 对照一个已知的单一来源身份检查措辞，而这两处是多源合成文档里**显式标记**的缺陷。当天，这次抓取变成了 S6——一条确定性的标记契约检查器，从 runtime 的溯源模块派生合法档位集合（一个真理源，契约变了检测器跟着变），标记契约外或契约不一致的标记。对同一份真实产物，S6 恰好标出人抓到的那两处缺陷，对契约内标记零误报；破坏验证确认每个分支承重。Layer 1 现在是六条信号；上面冻结的章节描述的是研究窗口内存在的五条。
*一条从验收测试里长出来的分布检测器（2026-08-28）。* 一个素材覆盖面回归家族——夜间跨域合成的引用几乎全部来自同一个日历月，因为一个固定的位置性采样窗口被钉在一个只追加归档的一端——被人眼连续抓到两次（第一次修复只是把偏置挪到了归档的另一端，而没有消除它；只有第二次重新设计才让采样变得内容感知）。当重新设计的验收数据到来——由人眼判定的、健康的五个月引用混合——验收判据本身当天就被机械化：每日观察者现在从合成中确定性地提取日期 token，当引用的月份塌缩时（少于三个不同月份，或单月超过 80% 的 token）就报异常。对被验收的真实产物它保持沉默；对历史上的单月形态它开火。

**P2. 第二次抓取给修复本身加上的约束。** 第五节报告了冻结规则三次约束**分析**。月份分布这一幕表明**修复**也需要被约束——第一次修复通过了它附带的全部测试，却只是挪动了缺陷——操作者在同一周把五条纪律写成了一条常设规则。(1) 守卫必须先断言用户会看到什么，再断言机制有效：第一次修复附带了 22 个绿色守卫测试，全部是机制检查，没有一个问用户会看到什么月份混合。(2) 位置性或容量性假设按类修而不按实例修：同一条管线还带着第二个位置性窗口——一个按字母序的截断，在未知时长里静默地从合成中丢掉了四个源，而页脚照样把它们算作已分析——第一次修复从没找过它。(3) 验收数据能被叙述成"设计的预期行为"的那一刻，就是攻击自己修复的时刻：全部是八月的引用分布曾被写第五节的同一对人合理化为"尾部窗口按设计工作"，直到人再看了一眼产品。(4) 每一个报告出来的计数都需要一个与实际发生的量对账的测试：合成页脚宣称十九个源经深度分析，而其中四个从未到达模型的上下文。(5) 容量 fixture 必须是生产量级：第一个守卫的 fixture 低于它守护的阈值，走的是"放得下、原样返回"分支——一个两次通过的假对照。纪律 (4) 贯穿后记其余部分，也正是它找到了这篇论文自己的表 5（第六节）的漏计。

**P3. 观测面自身也会 fail-plausible。** 诚实划界（第三节）量化了前作的定性主张：大多数静默故障住在接缝和运维里，不在内容里。部署时代以一种具体形式印证了这一点。2026-08-18 到 09-30 之间，一系列对抗性代码审计——一个人带着一个镜头问题去读 runtime 自己的**证据机制**："如果它所验证的那个东西已经失效了，它会说什么？"——找到了一个验证器家族，它们最让人安心的输出，恰恰是由它们自己的失效产生的。一个审计日志，整个日志被删掉时它的链校验器返回 `ok`。一个完整性校验器，唯一的生产调用点跑的是它的"重设基线"模式而从不跑"校验"模式，于是一个被清空的知识库会被吸收进下一次基线，第二天早上报告"完好"。一个 SLO 判定器，把两个从未被测量过的指标判为达标，因为一个哨兵值站在本该是测量值的位置上。一个推送前的密钥扫描，它的"无泄漏"行和"扫描器跑不动"无法区分。一个故障快照工具，它的 gateway 日志路径在整个仓库里没有任何写入方，并且在它恰恰为之存在的"服务挂起"场景里被调用方的超时杀掉，连已经收集到的日志一起丢弃。一条"LLM 完全不可用"的关键告警，它搜索的字符串在被监控程序的整个历史里从未被写过——而它有一个绿色单测，因为测试自己编造了那个字符串。一个声称的每周上游升级监控，四个月里没有 cron 条目、没有部署、没有告警路径；监控只存在于文档里。还有一条每周健康行，三个月里每周绿灯，一直在测 fallback 链的最后一跳，仿佛它是主模型：正确地回答着一个已经过期的问题。

我们报告这个家族有两个原因。第一，它是 fail-plausible 在证据平面上的对应物——不是一份把错误叙述成内容的输出，而是一个把自己的失效叙述成验证的验证器。第二，没有一条是内容观察者抓到的，也没有一条它能抓到：每一项都落在第三节的"否"桶里，没有面向用户的语义产物，而诚实划界存在的意义正是让这类事故被报告为范围外，而不是被悄悄记在仪器的功劳簿或过错簿上。这一类在部署时代的发现渠道是对抗性代码阅读，在显化的上游，与第五节（H3）一致。平衡没有从人移向机器；它从一种人的实践（看产品）移向了另一种（审问验证器）。

**P4. 反向形态，以及一个跑了五个月的。** 另有三起冻结后事故被记录，因为它们扩展了定义而不是落入定义。第一起（2026-09-22），一个 job 级质量闸把一份格式正确的分析判成解析失败——它的"解析率"拿评级条目数比输入条目数，这个比值在四个月前输出格式改变时就已经失去意义——然后丢弃了报告，用户只收到一条告警：一次健康的运行被叙述成失败。第二起（2026-09-23），一个投递层在任一通道失败时都报告全部失败；一个通道宕掉八小时，产生了假的关键告警、重复推送，以及每个 job 把投递记为失败，而另一个通道早已把一切送达。成功被叙述成失败是 fail-plausible 的反面，共享同一机制：一个名字——"解析率""已发送"——不再度量它所说的东西。第三起（2026-09-28 发现）是最纯粹的 D3 形态：大约五个月里，两个摄取 job 用知识库写入器不解析的标志调用它；写入器丢弃内容，写下一条整个正文就是第一个标志的笔记，打印"已记录"，返回成功——327 条这样的笔记，进入语义索引、周度回顾和夜间合成。它被发现，是因为操作者问了一个无关的验证问题，而一个本该为正的计数是零。三起都不在观察者的扫描集里；按登记的赛跑规则（H3）它们记在人的渠道，按第三节的规则记在范围外桶。它们是语料里那十六起在部署时代的对应物。

**P5. 观察者自己的账本没有停在十。** 第十一条，在窗口之外（2026-09-28）：观察者的源段扫描器对任何一天跑多次的源只保留**最后**一个同日段，所以对每一个这样的源，它一直只读着它所报告的产物的一个片段——静默地，因为多次运行的归档格式早于观察者。B 类，由找到它一直读漏的归档契约缺陷的同一次对抗审计抓到。它不在表 5 里，因为它晚于窗口；它在这里，因为账本只追加。

**P6. 登记的窗口，在修订时。** on 模式自 2026-07-26 起连续运行。只追加的判定账本在关窗条目之外没有任何触发裁决行，2026-10-05 对生产分数历史的一次计数核对一致：截稿后 56 行 on 模式记录，无一带触发裁决。我们没有重新制表第五节（计数核对不是制表）：登记的协议要求在读数据之前先声明一个新截稿，而我们拒绝在投稿前夕的修订里声明一个；安静窗口按登记原样成立，下一次制表将在它自己的截稿下追加到数据清单。八周里移动了的是检测器数量（五到六）、观察者自己的账本（窗口内八到十，总计十一）、约束修复的纪律（P2），以及这样的证据：部署时代的静默故障，和语料的三分之二一样，住在没有内容观察者看着的地方。循环继续运转，论文的常设结论也是：机械化的眼睛需要被看着——靠方法，不靠希望。

## 结语

前作结尾是那个应该让 agent 系统操作者害怕的故障画面：自信的段落，准点，语法完美，讲一场根本不存在的危机。这篇造了那个本该第一个去读那段话的东西。对我们记录在案的过去里的每一段这样的话，它都有效——确定性地、可证明地、每条检测器经破坏验证承重。对尚未写出的那些段落，它诚实地未经证明：离线持留召回 0/4，一个安静到无法打分的生产窗口，以及一个预测层，它的考试会按它自己的日程、在我们事先冻结的规则下到来。

我们可以毫无保留推荐的，是部署方法。先 shadow；读 shadow 数据之前登记 flip 判据；窗口打开之前冻结分析协议；翻之前先核实 flip 机制（我们十起观察者侧事故里有两起正是被这一步抓到的）；发表安静的窗口，因为你承诺过。并且给观察者自己记一本事故账本——我们的产生了十条，横跨四类分类学，包括一个幻觉出来的缺陷、两次假指控、一次静默无效的部署，而我们是**明知**裁判继承分类学的情况下造它的。眼睛可以被部分机械化。机械化的眼睛然后需要被看着——靠方法，不靠希望。
